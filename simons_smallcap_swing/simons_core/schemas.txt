Especificación: simons_core/schemas.py

1. Propósito

Contratos estructurales de datos del pipeline. Declara schemas canónicos,
valida shape/dtypes/nullability/PK/dominio/temporalidad. No imputa, no repara,
no transforma. Fail-fast y explícito.

2. Modelo formal

    D ⊨ S  <=>  columns_ok AND types_ok AND nulls_ok AND pk_unique
                AND domain_ok AND temporal_ok AND custom_validators_ok

3. Tipos declarativos

ColumnSpec:        nombre, dtype, nullable, required, allowed_values, min/max_value
ColumnPatternSpec: regex pattern para familias dinámicas (feature_*, y_fwd_ret_*)
DataSchema:        columns + patterns + PK + validators + version + date_column
ValidationIssue:   code + message + column
ValidationResult:  passed + issues + summary()

4. Schemas canónicos registrados (7)

prices_adjusted v1.0.0:
  PK(date, symbol). Columns: date, symbol, open, high, low, close, volume.
  Validators: high >= low, OHLC > 0, volume >= 0.

features v1.0.0:
  PK(date, symbol). Pattern: feature_[A-Za-z0-9_]+ (numeric, nullable, min 1).
  Validator: feature columns no overlap with PK.

labels v1.1.0:
  PK(date, symbol). future_ret_5d y binary_swing opcionales.
  Patterns: y_fwd_ret(_net)?_\d+d, y_class_*, y_rank_*.
  allow_extra_columns=True. SIN límite [-1,1] en retornos.
  Cambio v1.1.0: small caps superan ±100% en 20 días regularmente.

predictions v1.0.0:
  PK(date, symbol). Columns: date, symbol, score (required),
  prob_long ∈ [0,1] (optional), confidence ∈ [0,1] (optional).

universe v1.0.0:
  PK(date, symbol). Columns: date, symbol, is_eligible (binary, required),
  exchange, sector, industry, free_float_mcap_usd >= 0, adv20_usd >= 0.
  allow_extra_columns=True.

orders v1.0.0:
  Columns: date, symbol, side ∈ {BUY,SELL,B,S,1,-1}, quantity > 0,
  order_type (optional), limit_price (optional). Sin PK estricta.

fills v1.0.0:
  Columns: date, symbol, side, fill_quantity >= 0, fill_price > 0,
  commission >= 0 (optional), impact_cost >= 0 (optional). Sin PK estricta.

5. API pública

validate_schema(df, schema, asof_date=None) -> ValidationResult
assert_schema(df, schema, asof_date=None) -> None (raises SchemaValidationError)
get_schema(name) -> DataSchema
list_schemas() -> list[str]
register_schema(schema, overwrite=False) -> DataSchema

6. Dtype compatibility (runtime, no strict equality)

float/float64   -> is_float_dtype
int/int64       -> is_integer_dtype
numeric/number  -> is_numeric_dtype
binary          -> bool or int ∈ {0,1}
string/str      -> is_string_dtype or object with all str
date/datetime   -> is_datetime64_any_dtype
any             -> True

7. Issue codes

MISSING_COLUMN, UNEXPECTED_COLUMN, DUPLICATE_COLUMN_NAME, INVALID_DTYPE,
NULL_IN_NONNULLABLE, PRIMARY_KEY_VIOLATION, DOMAIN_VIOLATION,
NON_MONOTONIC_DATE, FUTURE_TIMESTAMP_VIOLATION, EMPTY_DATASET

8. Tests mínimos

- prices_adjusted con high < low -> DOMAIN_VIOLATION
- features sin feature_* columns -> MISSING_COLUMN
- labels con retorno = 2.3 (>100%) -> PASS (v1.1.0 fix)
- labels con columna y_fwd_ret_net_10d -> PASS (pattern match)
- predictions con prob_long = 1.5 -> DOMAIN_VIOLATION
- universe con free_float_mcap_usd < 0 -> DOMAIN_VIOLATION
- orders con quantity = 0 -> DOMAIN_VIOLATION
- fills con fill_price <= 0 -> DOMAIN_VIOLATION
- PK duplicada -> PRIMARY_KEY_VIOLATION
- Timestamp futuro con asof_date -> FUTURE_TIMESTAMP_VIOLATION
- register_schema + get_schema roundtrip
