Especificación: simons_core/io/parquet_store.py

1. Propósito

Snapshot store Parquet institucional. Un snapshot es una unidad lógica:

    S = (Π, Σ, M, τ)

Π = archivos Parquet, Σ = schema validado, M = manifest, τ = timestamp.
Schema validation antes de publicar. Publicación atómica. Lectura con
projection y filter. NO es un lakehouse (no Delta/Iceberg/Hudi).

2. Garantías

- Schema validation pre-publicación (fail-fast, NUNCA silent bypass).
- Publicación atómica: staging -> fsync -> rename -> pointer update.
- Snapshots versionados con manifest que gobierna visibilidad.
- Escrituras deterministas opcionales via canonical row ordering.
- Lectura con projection, filter y partition pruning.
- Corrupción detectada en validación; nunca servida en modo strict.

3. Cambio clave: imports fail-fast

simons_core.schemas es REQUERIDO, no opcional. Si no es importable,
el módulo no arranca. Un parquet store que silencia schema validation
y publica datos no validados es peor que uno que se niega a arrancar.

Viejo:  except Exception: DataSchema = Any; assert_schema = None
Nuevo:  except ImportError: raise ImportError("schemas module required")

Logging: fallback a stdlib logging si simons_core.logging no disponible.
Esto es aceptable porque logging no afecta correctitud de datos.

4. API pública

SnapshotStore(root_dir, schema_ref=None, ...):
  publish(df, ...) -> SnapshotMetadata
  read(snapshot_id=None, ...) -> pd.DataFrame
  read_metadata(snapshot_id) -> SnapshotMetadata
  list_snapshots() -> list[SnapshotMetadata]
  current_snapshot() -> SnapshotMetadata | None
  delete_snapshot(snapshot_id)
  compact(keep_latest=5)

Funciones libres:
  write_parquet(df, path, schema_ref=None, ...)
  read_parquet(path, columns=None, filters=None, ...)

5. Publicación atómica

    write to staging dir (temp)
    -> fsync all files
    -> rename staging to final snapshot dir
    -> update CURRENT pointer file
    -> write manifest

Si falla en cualquier paso, el snapshot parcial no es visible.

6. Manifest

JSON con: snapshot_id, schema_ref, schema_hash, row_count, column_count,
file_count, total_bytes, created_at_utc, data_hash.

7. Invariantes

I1. publish() SIEMPRE valida schema antes de escribir.
I2. Si schema validation falla, no se escribe nada.
I3. CURRENT pointer solo se actualiza tras publicación exitosa.
I4. read() de snapshot inexistente -> raise, no DataFrame vacío.
I5. Corrupción detectada (hash mismatch) -> raise en modo strict.

8. Tests mínimos

- publish + read roundtrip: datos idénticos
- publish con schema inválido -> SchemaValidationError, nada escrito
- CURRENT pointer apunta al último snapshot válido
- list_snapshots ordenado por timestamp
- delete_snapshot elimina archivos y actualiza pointer si era current
- read con projection: solo columnas solicitadas
