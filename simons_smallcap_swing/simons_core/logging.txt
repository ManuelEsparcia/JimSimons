Especificación: simons_core/logging.py

1. Propósito

Observabilidad estructurada del pipeline. JSON-line logging con envelope
versionado, redacción de secrets, propagación de contexto, instrumentación
de pasos y métricas. No implementa alertas ni métricas de negocio.

2. Esquema canónico de evento

    {
      "ts_utc": "2026-03-06T10:15:24.183Z",
      "level": "INFO",
      "logger": "simons.features",
      "event": "features_built",
      "schema_version": "1.0.0",
      "run_id": "run_20260306_001",
      "step": "feature_build",
      "payload": { "rows": 18420, "cols": 57 }
    }

Campos reservados: ts_utc, level, logger, event, payload, exception,
schema_version. Contextuales: run_id, step, module, asof_date, trace_id.

3. API pública

StructuredLogger:
  debug/info/warning/error/critical(event, **payload)
  exception(event, exc=None, error_code=None, **payload)
  bind(**fields) -> nuevo logger con contexto añadido
  child(suffix, **fields) -> logger hijo con nombre dotted

get_logger(name, run_context=None, sink=None, ...) -> StructuredLogger
bind_context(logger, **fields) -> StructuredLogger
with_step(logger, step, **fields) -> context manager
  Emite: step_started, step_completed (con duration_ms), step_failed

with_metric(logger, metric_name, step=None, **fields) -> context manager
  Emite: metric_started, metric_recorded (con payload del bag), metric_failed
  Uso: with with_metric(logger, "sharpe_oos") as bag: bag["value"] = 1.5

log_gate_result(logger, gate_name, result, **extra) -> None
  Emite: gate_evaluated con passed/score/threshold/reasons/metrics
  Nivel: info si passed, warning si not passed

4. Sinks

LogSink (Protocol): write(record)
StreamJsonSink: JSON a stream configurable
StdoutJsonSink: JSON a stdout
MemorySink: en memoria (para tests)
MultiSink: fan-out a múltiples sinks

5. Seguridad

Redacción automática de keys sensibles:
  api_key, token, password, secret, authorization, bearer_token, etc.
Serialización safe: numpy scalars, dataclasses, Path, UUID, Decimal, date.
Truncamiento configurable: max_text_chars=10_000, max_collection_items=1_000.

6. Invariantes

I1. Un log event siempre tiene ts_utc, level, logger, event, schema_version.
I2. Las keys en DEFAULT_REDACTED_KEYS se reemplazan por "[REDACTED]".
I3. with_step siempre emite start + (completed | failed). Nunca solo start.
I4. with_metric siempre emite started + (recorded | failed).
I5. Niveles: DEBUG < INFO < WARNING < ERROR < CRITICAL.
I6. require_run_id=True -> raise si no hay run_id en base_fields.

7. Tests mínimos

- MemorySink captura records con estructura correcta
- bind() preserva campos previos y añade nuevos
- with_step emite step_started + step_completed con duration_ms
- with_step con excepción emite step_failed con exception serializada
- with_metric emite metric_started + metric_recorded con bag contents
- log_gate_result emite gate_evaluated con passed/score/threshold
- Redacción: payload con key "api_key" -> "[REDACTED]"
- serialize_exception produce dict con type, message, traceback
