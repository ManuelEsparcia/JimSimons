Especificación: labels/label_qc.py

1. Propósito

Gatekeeper institucional de calidad de labels. Decide si los labels producidos
por build_labels.py o event_labels.py son suficientemente válidos para entrar
en entrenamiento, validación, backtesting o promoción. No describe estadísticas
— emite veredictos con severidad formal.

2. Dimensiones de QC

Validez estructural:
  - No duplicados (date, symbol)
  - No NaN/Inf en targets válidos
  - Consistencia entre valid_flag y exclusion_reason
  - Alineación PIT con features (si feature index disponible)

Validez estadística:
  - Cobertura por horizonte y fecha
  - Varianza cross-sectional positiva
  - Outlier detection (robust + economic sanity)
  - Drift de cobertura (CUSUM)
  - Balance de clases en clasificación

Validez temporal:
  - No leakage: event windows no se solapan con feature timestamps
  - Consistencia de calendario

3. Severidad de gates

FAIL: aborta el run. Duplicados, NaN en válidos, leakage detectado.
WARN: run degradado. Cobertura baja, drift, outliers, varianza colapsada.
INFO: solo diagnóstico. Conteos, estadísticas descriptivas.

gate_aggregation_policy = "fail_dominates": un FAIL → todo falla.

4. Inputs

Label store: output de build_labels o event_labels (parquet panel).
Feature index (opcional): para verificación de alineación PIT.
Price data (opcional): para sanity check de retornos vs precios.
Config: QCConfig con thresholds por horizonte.

5. QCConfig

    alignment_policy: exact_on_eligible_rows | best_effort
    duplicate_policy: fail | warn
    nan_policy: fail_if_valid | warn
    inf_policy: fail_if_valid | warn
    leakage_policy: fail | warn
    outlier_policy: robust_plus_economic_sanity | none
    drift_policy: cusum_on_coverage | none
    coverage_thresholds: {5: 0.05, 10: 0.05, 20: 0.05}
    variance_thresholds: {5: 1e-8, 10: 1e-8, 20: 1e-8}
    outlier_zscore_threshold: 10.0
    max_return_absolute: 5.0 (500% — economic sanity)
    cusum_sensitivity: 2.0
    policy_version: 1.0.0

6. Checks principales

structure.no_duplicates:           (date,symbol) unique. FAIL.
structure.no_nan_in_valid:         target notna where valid_flag. FAIL.
structure.no_inf_in_valid:         target finite where valid_flag. FAIL.
structure.valid_reason_consistency: valid_flag ↔ exclusion_reason coherent. FAIL.
alignment.feature_date_match:     feature dates ⊆ label dates. FAIL/WARN.
alignment.pit_no_leakage:         event_end < feature_timestamp. FAIL.
coverage.h{H}.min_threshold:      coverage ≥ threshold. WARN.
coverage.h{H}.drift_cusum:        CUSUM on coverage series. WARN.
variance.h{H}.cross_section:      var > threshold por fecha. FAIL (primary).
outlier.h{H}.robust_zscore:       |z| < threshold. WARN.
outlier.h{H}.economic_sanity:     |ret| < max_return_absolute. WARN.
classification.h{H}.balance:      clases no colapsadas. WARN.

7. Output

QCArtifacts:
  gate_results: list[QCRecord] con severidad y métricas
  summary_stats: DataFrame con estadísticas por horizonte y fecha
  coverage_series: DataFrame con cobertura temporal
  alignment_report: dict con diagnóstico de alineación
  manifest: dict con config hash, input hashes, timestamp

Persistencia: qc_report_{run_id}.json, qc_summary_{run_id}.parquet

8. Integración simons_core

QCRecord.to_gate_result() produce GateResult combinable con GateResult.combine().
Esto permite que el pipeline use gates de labels junto con gates de features,
models, etc. bajo AND semántico.

9. Tests mínimos

- Duplicados en (date,symbol) → FAIL
- NaN en target donde valid_flag=True → FAIL
- Inf en target → FAIL
- valid_flag=True con exclusion_reason presente → FAIL
- Cobertura < threshold → WARN
- Varianza cross-sectional = 0 en primary horizon → FAIL
- Retorno > 500% → WARN (economic sanity)
- Feature timestamp > event_end → FAIL (leakage)
- CUSUM detect coverage drift → WARN
