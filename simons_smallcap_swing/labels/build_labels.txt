Especificación: labels/build_labels.py

1. Propósito

Construye la capa canónica de targets forward del sistema: labels PIT,
multi-horizonte, netos de costes, con neutralización, clasificación,
ranking y jerarquía formal de exclusión. Define qué aprende el modelo
bajo qué convención de ejecución y con qué fricciones económicas.

2. Cadena del pipeline

    data/* → universe/ → features/ → execution/cost_model
    → labels/build_labels.py → labels/purged_splits.py → models/*

3. Pregunta que responde

"Dada una observación (i,t) y una convención operativa, cuál es el target
forward económicamente realizable, temporalmente válido y trazable que debe
asociarse a esa fila de features?"

4. Defaults canónicos

    horizons = [5, 10, 20]
    primary_target = y_fwd_ret_net_10d
    return_mode = close_to_close
    decision_lag = 1
    net_of_costs = True
    missing_cost_policy = strict_invalidate
    neutralization_mode = sector_beta_size_liquidity
    classification_default = tail_20_20_on_net_10d
    label_mode = fixed_horizon

Todo desvío queda marcado como non_canonical en manifest.

5. Target económico base

    y_gross(i,t,h) = P_exit(i, t+lag+h) / P_entry(i, t+lag) - 1
    y_net(i,t,h) = y_gross - C_entry - C_exit - C_carry

Convenciones soportadas: close_to_close, close_to_open, open_to_close, open_to_open.
Fechas resueltas sobre calendario real de trading (no business days genéricos).

6. Política de costes

4 modos: strict_invalidate (default), fallback_proxy, partial_costs, zero_imputation.
Con strict_invalidate: si falta cualquier componente material, la obs se invalida.
Componentes: entry_cost, exit_cost, carry_cost (borrow + financing).
Incertidumbre opcional: cost_mean, cost_var → CI intervals.

7. Clasificación (CORRECCIÓN v1.1)

Tail classification ahora usa rank(pct=True, method="average") en vez de
quantile(). Esto elimina ambigüedad de empates: con quantile(), observaciones
en el boundary producían clases de tamaño variable entre fechas. Con rank-based,
el top 20% siempre es exactamente el 20% superior del cross-section.

    y_cls_tail(i,t,h) = +1 si rank_pct >= top_q, -1 si rank_pct <= bot_q, 0 otherwise

Binary: y_cls_up(i,t,h) = 1{y_star > threshold}

8. Neutralización (inline, delegable a neutralized_targets.py)

    y_t,h = X_t β_t,h + ε_t,h → y_neut = ε

Estimador: weighted_ridge. Lambda: fija o grid search (in-sample MSE).
Exposiciones: intercept + sector dummies + beta + log(mcap) + liquidity.
Invalidación si: n < n_min, X mal condicionada, varianza residual degenerada.

NOTA: la implementación en neutralized_targets.py es superior (CV temporal,
Huber, más diagnósticos). Consolidación pendiente.

9. Jerarquía de exclusión (12 razones, prioridad estable)

 1. OUT_OF_SAMPLE_DATE
 2. NOT_IN_UNIVERSE
 3. MISSING_ENTRY_PRICE
 4. MISSING_EXIT_PRICE
 5. INCOMPLETE_FORWARD_WINDOW
 6. CORPORATE_ACTION_UNSAFE
 7. TRADING_HALT_OR_SUSPENSION
 8. DELIST_AMBIGUOUS
 9. MISSING_COST_INPUT
10. MISSING_EXPOSURES
11. NEUTRALIZATION_FAILED
12. QC_REJECTED

label_valid_flag = True solo si ninguna exclusión activada Y target notna.

10. Delistings y corporate actions

Delistings: si existe delisting_return PIT → incorporar. Si no monetizable
y sin return → DELIST_AMBIGUOUS. Prohibido usar último precio como fallback.
Corporate actions: splits, mergers, tenders, halts → CORPORATE_ACTION_UNSAFE.

11. QC integrado

10+ checks con severidad FAIL/WARN/INFO:
- structure.no_duplicate_date_symbol (FAIL)
- universe.labels_within_universe_contract (FAIL)
- coverage.h{H} (WARN)
- variance.cross_section_positive.h{H} (FAIL si primary)
- classification.non_collapsed.h{H} (WARN)
- costs.net_target_requires_costs.h{H} (FAIL)

_enforce_qc(): FAIL → aborta el run.

12. Schema validation (NUEVO v1.1)

Al final de build_labels(), el output se valida contra LABELS_SCHEMA
(con patterns y_fwd_ret_*d) si simons_core está disponible.

14. Tests mínimos

- Forward returns correctos en series sintéticas con lag=1
- strict_invalidate invalida obs sin costes
- Clasificación tail produce clases de tamaño estable (rank-based)
- Neutralización con factores conocidos produce residuales ~0
- Jerarquía determinista: razón principal estable bajo multi-exclusion
- Delisting con return PIT → incorporado. Sin return → DELIST_AMBIGUOUS
- QC FAIL aborta el run
- Schema validation ejecuta si simons_core disponible
