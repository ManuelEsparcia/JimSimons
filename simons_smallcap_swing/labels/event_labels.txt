Especificación: labels/event_labels.py

1. Propósito

Labels event-driven: targets definidos sobre episodios discretos de información
(earnings, noticias, gaps, breakouts, vol shocks, microestructura) en vez de
panel uniforme fecha-símbolo. Complementa build_labels.py para triggers donde
el proceso generador de retornos cambia estructuralmente alrededor del evento.

2. Pregunta que responde

"Dado un trigger event-driven verificable para símbolo i, cuándo pasa a ser
operable, qué episodio económico define, y cuál es el outcome forward
económicamente realizable asociado a ese episodio?"

3. Taxonomía canónica (6 familias)

EARNINGS:              resultados periódicos, guidance. Horizons default: 1,3,5,10d
CORP_NEWS:             M&A, financiación, litigio, contratos. Horizons: 1,3,5,10d
OPEN_GAP:              gap de apertura > umbral. Horizons: 1,2,5d
TECH_BREAK:            breakout, breakdown, reversal extremo. Horizons: 3,5,10d
VOL_SHOCK:             volumen o volatilidad anómala. Horizons: 1,3,5d
MICROSTRUCTURE_SHOCK:  halt, spread shock, colapso liquidez. Horizons: 1,2,3d

Familias no listadas → event_family_status = "experimental".

4. Timestamps fundamentales (por evento)

    t_occ:   ocurrencia económica
    t_pub:   publicación
    t_known: conocimiento por el sistema
    t_trad:  primer instante operable (≥ t_known)

Resolución: pre_market → next open. after_close → next open.
intraday → same session si allow_intraday_immediate, else next open.

5. Convenciones entry/exit

open_to_close, open_to_open, close_to_close,
event_to_next_close, event_to_next_open.

6. Overlap policy

first_event_wins_with_cooldown (default):
  Cooldown = max(horizons) del evento. Durante cooldown, nuevos eventos
  del mismo símbolo son rechazados (OVERLAP_REJECTED).
merge_same_episode:
  Eventos del mismo símbolo dentro del cooldown se agrupan bajo episode_group_id.

7. Costes (CORRECCIÓN CRÍTICA v1.1)

ANTES: config_missing_entry_cost() y config_missing_exit_cost() siempre
devolvían 0.0. Todos los event labels eran "netos" con coste cero → sesgo
optimista de 10-30bps/trade en small caps.

AHORA: con strict_invalidate (default), devuelven NaN → observación excluida.
Con fallback_proxy, usan CostPolicy.fallback_entry_bps / fallback_exit_bps.

Este era el bug con mayor impacto en P&L del módulo labels.

8. Abnormal returns

Modos: none, market_adjusted, sector_adjusted, sector_market_adjusted,
matched_control, factor_adjusted.
auto → sector_market_adjusted para corporate, none para technical.

9. Jerarquía de exclusión (13 razones)

UNKNOWN_EVENT_TYPE, TIMESTAMP_AMBIGUOUS, NOT_IN_UNIVERSE,
MISSING_ENTRY_PRICE, MISSING_EXIT_PRICE, INCOMPLETE_OUTCOME_WINDOW,
OVERLAP_REJECTED, TRADING_HALT_OR_SUSPENSION, CORPORATE_ACTION_UNSAFE,
DELIST_AMBIGUOUS, MISSING_COST_INPUT, BENCHMARK_UNAVAILABLE, QC_REJECTED.

10. Output por episodio

event_id, episode_group_id, symbol, event_type, event_family_status,
timestamps (occ, pub, known, tradable), horizon_days,
entry/exit session+px, event_ret_gross, event_ret_net, event_alpha,
cost_entry, cost_exit, cost_carry, event_exclusion_reason,
event_label_valid_flag, label_event_cont/bin/tri.

11. Performance concern

16 instancias de iterrows(). En universos grandes (3000 símbolos × 6 tipos ×
5000 fechas), esto es 100-1000x más lento que vectorización.
Consolidación pendiente.

12. Tests mínimos

- strict_invalidate sin tabla de costes → todos los event labels excluidos (NaN cost)
- fallback_proxy → costes del proxy aplicados
- Overlap: dos eventos < cooldown del mismo símbolo → segundo OVERLAP_REJECTED
- Timestamp resolution: after_close → next open session
- Earnings con horizons [1,3,5,10] → 4 filas por evento
- Delisting durante outcome window → delisting_return_used si disponible
- UNKNOWN_EVENT_TYPE para familia no canónica
