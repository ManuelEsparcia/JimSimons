Especificación: labels/purged_splits.py

1. Propósito

Construye particiones temporales del sistema para train/valid/test sobre
paneles (date, symbol), garantizando que la evaluación sea temporalmente
válida y robusta frente a label leakage, serial dependence y dependencias
inducidas por ventanas forward, decision lag y features con memoria temporal.

No "parte fechas". Define formalmente qué observaciones pueden convivir en
train y test una vez se tiene en cuenta la ventana efectiva de dependencia.

2. Modos de split (3)

purged_kfold:      K-fold temporal con purga de ventanas forward + embargo.
                   Folds sobre bloques de fechas, no sobre rows.

walk_forward:      Train creciente o rolling, test sequencial.
                   WalkForwardSpec: test_size_dates, step_size_dates, valid_size_dates.

cpcv:              Combinatorial Purged Cross-Validation (López de Prado).
                   CPCVSpec: n_groups, n_test_groups.
                   Genera C(n_groups, n_test_groups) folds combinatoriales.

3. Horizonte efectivo

    h_eff = max(h para h en horizons) + decision_lag

Este es el intervalo durante el cual el label de una observación depende
de información futura. Ninguna observación cuyo intervalo [t, t+h_eff]
se solape con un bloque de test puede estar en train.

4. Embargo (MEJORA v1.1 — adaptive)

4 políticas:

fixed_days:              Entero fijo configurable.
pct_of_test:             Fracción del bloque de test.
feature_memory_aware:    max(feature_memory, h_eff). Default.
adaptive (NUEVO):        max(feature_memory, h_eff) + h_eff como margen de
                         seguridad. Para momentum features con lookback 60d y
                         horizonte 20d → embargo = 80d en vez de 20d.

WARNING automático si embargo < horizonte efectivo:
  "Embargo (X days) is less than effective horizon (Y days).
   This is likely insufficient to prevent label leakage."

5. Event intervals

Para cada observación:
    event_start = t + decision_lag (fecha de entrada)
    event_end = t + decision_lag + max_horizon (fecha de salida)

build_event_intervals() produce un DataFrame con:
    date, symbol, event_start, event_end, effective_horizon
que purged_splits consume para purgar train de observaciones cuyas
ventanas se solapan con el test.

6. Fold definition

FoldDefinition:
    fold_id: str
    train_dates: tuple[Timestamp, ...]
    valid_dates: tuple[Timestamp, ...] (puede ser vacío)
    test_dates: tuple[Timestamp, ...]
    embargo_dates: tuple[Timestamp, ...] (entre train y test)

Invariante: train ∩ (test ∪ embargo) = ∅ para todo fold.

7. SplitConfig

    split_mode: purged_kfold | walk_forward | cpcv
    n_folds: int (para kfold y cpcv)
    embargo_policy: fixed_days | pct_of_test | feature_memory_aware | adaptive
    fixed_embargo_days: int | None
    pct_embargo: float | None
    primary_feature_memory: int | None
    walk_forward_spec: WalkForwardSpec | None
    cpcv_spec: CPCVSpec | None
    horizons: list[int] (de build_labels)
    primary_horizon: int
    decision_lag: int
    leakage_audit_policy: fail | warn | off
    policy_version: str

8. Leakage audit

Tras construir folds, se verifica que ningún event interval de train se
solape con fechas de test (ni viceversa). Si leakage_audit_policy = "fail"
→ LeakageError. Si "warn" → log warning.

9. Compatibilidad con build_labels

Consume split_compatibility_{run_id}.json:
    event_windows: {h}d → event_start_col, event_end_col
    primary_target, primary_horizon, decision_lag

10. Invariantes

I1. Folds se construyen sobre fechas, no sobre rows.
I2. El número de símbolos por fecha puede variar pero no redefine la lógica.
I3. train ∩ test = ∅ siempre. train ∩ embargo = ∅ siempre.
I4. embargo ≥ horizonte efectivo (warning si no).
I5. Con n_folds y walk_forward, todas las fechas aparecen en al menos 1 test.
I6. CPCV genera C(n,k) folds. Con n=6, k=2 → 15 folds.
I7. Determinismo: mismos inputs + config → mismos folds.

11. Tests mínimos

- purged_kfold: train ∩ test = ∅ en todos los folds
- walk_forward: test blocks secuenciales sin gaps
- cpcv: número de folds = C(n_groups, n_test_groups)
- Embargo adaptive con feature_memory=60, horizon=20 → embargo ≥ 80
- Embargo < horizon → warning emitido
- Embargo fixed_days=0 con horizon=20 → warning
- Leakage audit: event interval de train solapando test → LeakageError
- Todas las fechas del dataset aparecen en al menos 1 fold de test
- Determinismo: 2 ejecuciones con mismos inputs → folds idénticos
