Especificación: data/universe/build_universe.py

1. Propósito

Construye el universo invertible diario PIT: para cada fecha de trading,
qué instrumentos eran elegibles para research, ranking y ejecución,
usando solo información disponible en esa fecha. Si el universo tiene
survivorship bias, todo downstream (features, labels, backtest) hereda
el error.

2. Modelo formal

    U_build: (listing_master, calendar, features_asof, config)
             → (universe_history, current_snapshot, exclusions, stats)

3. Reglas de elegibilidad (UniverseRules)

security_type_whitelist: ["CS"] (common stock only).
exchange_whitelist: ["NYSE", "NASDAQ", "AMEX"].
min_price: 1.0 (penny stock filter).
min_adv20: 50_000 (20-day avg dollar volume).
mcap_band: [50M, 2B] (small cap definition).
min_days_since_listing: 21 (avoid IPO noise).
halt_exclude: True.
suspension_exclude: True.

4. Pipeline

load_listing_master() → _build_life_windows()
→ _apply_forward_fill_if_enabled() → apply_filters()
→ compute_transitions() → compute_daily_stats()
→ compute_soft_qc_checks() → build_universe()

5. Filtering (apply_filters)

Para cada (symbol, date):
  1. NOT_YET_LISTED si date < list_date.
  2. DELISTED si date > delist_date.
  3. BAD_SECURITY_TYPE si tipo no está en whitelist.
  4. BAD_EXCHANGE si exchange no está en whitelist.
  5. HALTED / SUSPENDED si flag activo en esa fecha.
  6. TOO_YOUNG_SINCE_LISTING si days_since_listing < min.
  7. PRICE_BELOW_MIN, ADV20_BELOW_MIN, MCAP_OUT_OF_BAND.
  8. MISSING_* si dato falta y MissingDataPolicy = exclude.

Jerarquía de exclusión determinista: la primera razón que aplica gana.
MembershipState resultante: ELIGIBLE o INELIGIBLE_*.

6. Transitions

compute_transitions(): detecta ENTRY, EXIT_*, REENTRY, HOLD por symbol
entre fechas consecutivas. Esto alimenta survivorship audit y churn stats.

7. Output

universe_history_{run_id}.parquet: panel (date, symbol, membership_state,
  exclusion_reason, transition, eligible_flag).
universe_current_{run_id}.parquet: snapshot del último día.
universe_exclusions_{run_id}.parquet: detalle de exclusiones.
universe_stats_{run_id}.parquet: stats diarias (n_eligible, n_entry, n_exit, churn).
manifest.json: config_hash, input hashes, date range, run_id.

8. Invariantes

I1. PIT estricto: list_date, delist_date, features usados son ≤ date.
I2. Para cada (date, symbol), hay exactamente 1 membership_state.
I3. Si membership_state = ELIGIBLE → exclusion_reason is None.
I4. Si exclusion_reason is not None → membership_state ≠ ELIGIBLE.
I5. Transitions son consistentes: ENTRY solo si día anterior ≠ ELIGIBLE.
I6. Determinista: mismos inputs + config → mismo output.

9. Tests mínimos

- Símbolo listado el 2024-01-15: no aparece como ELIGIBLE el 2024-01-14.
- Símbolo delistado: INACTIVE_POST_DEATH después de delist_date.
- Precio $0.50 con min_price=1.0: PRICE_BELOW_MIN.
- ADV20 = 30K con min_adv20=50K: ADV20_BELOW_MIN.
- MCap $3B con band [50M, 2B]: MCAP_OUT_OF_BAND.
- Halted flag activo: INELIGIBLE_HALTED.
- Transition ENTRY cuando pasa de ineligible a eligible.
- Stats: n_eligible == count(eligible_flag == True) por date.
