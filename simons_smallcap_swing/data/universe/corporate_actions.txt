Especificación: data/universe/corporate_actions.py

1. Propósito

Normaliza, resuelve conflictos y clasifica corporate actions de múltiples
providers en un registro canónico PIT. Alimenta adjust_prices (factores
de ajuste), build_universe (eligibilidad post-event), y labels (exclusion
por corporate action unsafe).

2. Taxonomía de eventos (CanonicalEventType + EventFamily)

EventFamily agrupación: structural (split, reverse_split, stock_dividend),
  distribution (cash_dividend, special_cash_dividend),
  reorganization (merger, acquisition, spinoff, bankruptcy_reorg),
  administrative (ticker_change, name_change, exchange_change, share_class_change),
  lifecycle (delisting, relisting, rights_issue, tender_offer).

EVENT_TYPE_TO_FAMILY: mapping de 17+ event types a 5 families.
DEFAULT_EVENT_TYPE_ALIASES: normalización de strings ("stock_split" → "split").

3. Pipeline

Ingest raw events (multi-provider) → normalize event types
→ temporal alignment (visible_ts_utc) → conflict detection
→ cluster matching → conflict resolution → persist canonical.

4. Normalización

NormalizationConfig: date parsing, symbol normalization, column mapping.
Cada evento requiere: symbol, event_type, application_date, source_provider.
Campos opcionales: ex_date, effective_date, ratio, amount, visible_ts_utc.

5. Conflict detection y clustering (MatchingConfig)

Cluster: agrupa eventos de múltiples providers que refieren al mismo
  evento económico real. Matching por: (symbol, event_type, date_window).
  date_window configurable (default: ±3 business days).

Conflictos: mismo cluster pero ratios/amounts discrepantes.
ConflictConfig: tolerance_pct, provider_priority_list.
Resolución: provider con mayor prioridad gana. Conflicto logueado.

6. GateResult (usa shared de universe.__init__)

Gates por etapa:
  normalization_gate: % rows parseadas correctamente.
  coverage_gate: % symbols con al menos 1 evento.
  conflict_gate: % clusters sin conflictos materiales.
  lineage_gate: trazabilidad de cada evento canónico a su fuente.

7. Output

canonical_events.parquet: eventos normalizados con cluster_id, chosen flag.
conflicts.parquet: conflictos detectados con detalle de discrepancia.
clusters.parquet: agrupación de eventos equivalentes.
manifest.json: config_hash, provider hashes, coverage stats.

8. Invariantes

I1. PIT: visible_ts_utc ≤ asof para todo evento usado.
I2. Cada cluster tiene exactamente 1 evento "chosen" por prioridad.
I3. event_type ∈ CanonicalEventType.values después de normalización.
I4. Eventos sin visible_ts_utc usan filed_date como fallback.
I5. Terminal events (delisting, merger, acquisition) marcan end-of-life.

9. Tests mínimos

- "stock_split" normaliza a "split".
- 2 providers con mismo split ratio → cluster sin conflicto.
- 2 providers con ratios diferentes → conflict logged, priority wins.
- Evento con visible_ts > asof → excluido del canonical set.
- Delisting event → TERMINAL_EVENT_TYPES match.
- Cluster con 3+ providers → chosen = highest priority.
