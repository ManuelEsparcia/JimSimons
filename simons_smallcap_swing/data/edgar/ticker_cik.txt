Especificación: data/edgar/ticker_cik.py

1. Propósito

Construye y mantiene el mapping bidireccional ticker ↔ CIK (Central Index
Key de SEC) con resolución temporal. Un ticker puede mapear a diferentes
CIKs en diferentes fechas (ticker changes, spin-offs). El mapping PIT
es prerequisito para todo el pipeline EDGAR.

2. Problema que resuelve

"¿Qué CIK corresponde al ticker AAPL en fecha t?" No es trivial:
- Tickers se reusan (CANO fue primero Cano Health, luego reasignado).
- Una empresa puede tener múltiples tickers (classes A/B/C).
- Ticker changes (FB → META) deben resolverse por fecha.
- Fuentes de mapping contradictorias (SEC, exchanges, providers).

3. Fuentes de datos

Multi-source con corroboración:
- SEC EDGAR company tickers JSON (bulk)
- SEC full-text search por ticker
- Provider-supplied mappings (CSV/parquet)
- Historical ticker change databases

Cada fuente tiene: source_name, confidence, priority, effective_from/to.

4. Pipeline

load_candidate_sources() → attach_corroboration_and_metadata_score()
→ resolve_symbol_history() → build_history() → build_current()

5. Resolución de conflictos

Cuando múltiples fuentes discrepan:
- Priority por source_name (configurable).
- Corroboration score: cuántas fuentes independientes confirman el mapping.
- Temporal continuity: el mapping previo tiene inercia (hysteresis).
- Segmentation: SegmentDecision con segment_id, effective_from/to.

resolve_pit_identity(history, symbol, asof) → DataFrame con el CIK vigente.

6. Output

history.parquet: (symbol, cik, source, confidence, effective_from, effective_to, ...)
current.parquet: snapshot vigente (symbol, cik, company_name, ...)
conflicts.parquet: conflictos no resueltos para revisión manual.
manifest.json: config_hash, source hashes, run_id, asof.

7. Invariantes

I1. Todo CIK es 10 dígitos zero-padded.
I2. Para cada (symbol, date) hay exactamente 0 o 1 CIK activo.
I3. Los rangos effective_from/to no se solapan para un mismo symbol.
I4. PIT estricto: el mapping en fecha t usa solo datos disponibles ≤ t.

8. Tests mínimos

- Ticker con cambio de nombre: FB→META resuelve correctamente por fecha.
- Fuentes contradictorias: la de mayor priority+corroboration gana.
- Rango temporal: effective_from/to no overlap para mismo symbol.
- normalize_cik consistente con edgar.__init__.
