Especificación: data/edgar/point_in_time.py

1. Propósito

Construye la tabla PIT (point-in-time) de fundamentales: para cada
(CIK, metric, asof_date), selecciona el valor que habría sido
conocido en esa fecha, usando solo filings aceptados antes de asof.
Este es el módulo que convierte "datos financieros" en "datos
financieros utilizables sin lookahead".

2. Problema que resuelve

Un filing de Q3 2024 puede ser aceptado por SEC el 2024-11-05 a las
17:32 UTC. Si tu sistema procesa datos al cierre del 2024-11-04, ese
filing NO existía. Si lo usas, introduces lookahead bias que infla
artificialmente cualquier señal basada en fundamentales.

point_in_time garantiza: solo usas lo que existía en t.

3. Asof grid

resolve_asof_grid(start, end, frequency) → lista de timestamps.
Default: diario a las 18:00 UTC (post-market, pre-overnight batch).
Configurable: asof_time_utc = "18:00:00".

Para cada asof, se buscan filings con acceptance_datetime < asof.

4. Selection logic (por métrica, por asof)

select_candidates_for_asof(facts, mapping, asof, cfg):
  1. Filter facts donde filed_date < asof (PIT gate).
  2. Si hay metric_mapping activo → filtrar por canonical_metric.
  3. Resolver conflictos cuando hay múltiples valores para misma métrica:
     - Priority: más reciente fiscal period primero.
     - Entre mismo period: último filing (restated > original).
     - selection_priority_columns: filed_date desc, form_priority, accession desc.
  4. _resolve_selection_conflicts: groupby (cik, metric, period) → pick winner.

5. Staleness y quality

apply_staleness_and_quality(selected, asof, cfg):
  - staleness_days = (asof - filed_date).days
  - Age buckets: fresh (≤90d), recent (≤180d), aging (≤365d), stale (>365d).
  - quality_score basado en: form_type priority, staleness, is_amended.
  - stale_threshold configurable: datos > N días → flagged como stale.

6. Full panel construction

build_full_panel(facts, submissions, mapping, flags, asof_grid, cfg):
  Para cada asof en grid → select_candidates → apply_staleness → output row.

Output: panel con (cik, symbol, asof_date, metric, value, unit,
fiscal_year, fiscal_period, filed_date, staleness_days, quality_score,
age_bucket, is_stale, form_type, accession_number).

7. Flags integration

join_flags(candidates, flags, cfg): incorpora filing flags
(late_filer, restatement, nt_filing, etc.) como columnas adicionales.

8. Invariantes

I1. Nunca se usa un filing con acceptance_datetime > asof.
I2. Para cada (cik, metric, asof), hay exactamente 0 o 1 valor seleccionado.
I3. El valor seleccionado es el más reciente fiscal period con el
    último filing disponible.
I4. staleness_days ≥ 0 siempre.
I5. Idempotente: mismo (config, inputs, asof_grid) → mismo output.

9. Tests mínimos

- Filing aceptado 1 día después de asof → excluido del panel.
- Filing aceptado 1 día antes de asof → incluido.
- Restatement posterior reemplaza valor original para misma métrica+periodo.
- Staleness calculada correctamente: asof - filed_date.
- Age bucket correcto: 45d → "fresh", 200d → "aging", 400d → "stale".
- Dos filings para misma métrica+periodo → el más reciente gana.
