Especificación: data/edgar/fetch_companyfacts.py

1. Propósito

Descarga company facts (XBRL datos financieros estructurados) de SEC EDGAR.
Cada company fact contiene todos los valores reportados para cada concepto
XBRL (revenue, assets, etc.) con sus períodos, unidades y filing metadata.

2. API de SEC

Endpoint: https://data.sec.gov/api/xbrl/companyfacts/CIK{cik}.json
- Payload masivo: todos los facts XBRL ever reported por la empresa.
- Estructura: {facts: {taxonomy: {concept: {units: {unit: [values]}}}}}

Usa sec_fetch_json() compartido de edgar.__init__.

3. IngestConfig

Hereda patrón de fetch_submissions: user_agent, rate_per_second,
max_retries, backoff_*, cik_list, output_dir, asof, run_id.
Adicional: taxonomy_filter (default: ["us-gaap", "dei"]).

4. Payload validation

validate_payload_structure(payload, cik):
- "facts" key must exist
- Each taxonomy must be a dict of concepts
- Each concept must have "units" dict
- Reporta PayloadSchemaError si estructura es inválida.

5. Fact row construction

build_fact_row(cik, taxonomy, concept, unit, value_record):
- Extrae: val, start, end, fy, fp, form, filed, accn, frame
- parse_date para start/end/filed
- parse_numeric para val
- sanitize_accession_number para accn

6. Output

raw/{asof}/{run_id}/{cik}_facts.json: envelope crudo.
parsed/{asof}/{run_id}/companyfacts.parquet: tabla normalizada.
  Columnas: cik, taxonomy, concept, unit, value, start_date, end_date,
  fiscal_year, fiscal_period, form_type, filed_date, accession_number.

7. FetchResult (por CIK)

cik, status, n_facts_total, n_taxonomies, n_concepts,
http_status, error_message, elapsed_seconds.

8. Tests mínimos

- Parse de JSON sintético con estructura facts/taxonomy/concept/units.
- validate_payload_structure detecta payload malformado.
- parse_numeric(None) is None, parse_numeric("not_a_number") is None.
- Fact row tiene todos los campos esperados y tipos correctos.
- Idempotencia: raw envelope existente → skip.
