Especificación: data/edgar/parse_xbrl.py

1. Propósito

Transforma los company facts crudos (JSON de SEC) en una tabla normalizada
de métricas financieras con resolución de unidades, períodos y mapping a
nombres canónicos. Este es el paso que convierte datos XBRL heterogéneos
en una tabla homogénea consumible por point_in_time.py.

2. Problema que resuelve

Los XBRL facts de SEC son caóticos:
- Mismo concepto con diferentes taxonomías (us-gaap vs dei vs custom).
- Unidades inconsistentes (USD, USD/shares, shares, pure).
- Períodos que pueden ser instantáneos (balance) o duraciones (income).
- Una empresa puede reportar la misma métrica con tags diferentes en
  diferentes filings.

parse_xbrl aplica reglas de mapping configurables para normalizar esto.

3. Mapping rules (DEFAULT_MAPPING_RULES)

Lista de reglas [{taxonomy, tag_pattern, canonical_name, unit_filter,
period_type, priority}]. Ejemplo:
  us-gaap / RevenueFromContract* → "revenue" / USD / duration / priority=10
  us-gaap / Revenues → "revenue" / USD / duration / priority=5

Cuando múltiples reglas matchean, gana la de mayor priority.

resolve_mapping(config, taxonomy, tag) → MappingDecision con:
  canonical_name, priority, unit_decision, period_decision.

4. Unit normalization

UnitDecision: canonical_unit, conversion_factor, is_per_share.
Aliases configurables: {"usd": "USD", "usdpershare": "USD/shares"}.
canonicalize_unit(value, aliases) → normalized string.

5. Period classification

PeriodDecision: period_type ∈ {instant, duration}, fiscal_alignment.
Balance sheet items → instant (end date only).
Income/cash flow → duration (start + end dates).

6. Pipeline

load_submissions_metadata() → load_companyfacts_candidates()
→ build_accession_lookup() → resolve mappings → build output table.

Output table columns:
  cik, symbol, canonical_metric, value, unit, period_type,
  start_date, end_date, fiscal_year, fiscal_period,
  form_type, filed_date, accession_number,
  taxonomy, original_tag, mapping_priority.

7. Persistencia

parsed_xbrl/{asof}/{run_id}/metrics.parquet
parsed_xbrl/{asof}/{run_id}/mapping_log.parquet (qué regla mapeó qué)
parsed_xbrl/{asof}/{run_id}/unmapped.parquet (tags sin mapping)

8. Tests mínimos

- Mapping rule con mayor priority gana sobre menor priority.
- Revenue tag → canonical_name "revenue".
- Unit "USD" y "usd" normalizan al mismo valor.
- Period type: Assets → instant, Revenue → duration.
- Tag sin mapping rule → aparece en unmapped.parquet.
- Accession number → sanitize_accession_number format.
